# CreatorMart — Autonomous Upgrade Roadmap

> This file is the shared brain between the human owner, the daily **self-upgrade**
> run and any manual session. The unattended job (`backend/app/ops/daily.py`)
> reads this every day at the date change, ships **exactly one** item from
> **Next**, then moves it to **Done**. New ideas are appended, never lost.

## Mission
Grow the platform into a self-running **content + affiliate + own-products
business**: make daily videos, publish them, sell products (own stock + affiliate
deals), collect payments (UPI intent / COD), fulfil delivery — and keep getting
better on its own, every day, with no human babysitting.

## Rules (non-negotiable)
- One small, safe, **additive** change per day. Backwards compatible. Keep the code style.
- Never break the live site. Never invent credentials (FB/IG passwords, UPI id, API keys).
- Never delete user data. The *self-upgrade* run itself must not introduce **new** kinds of auto-posting; the owner's own scheduled uploads and the growth agent's gap recovery (re-sending a post the schedule already intended) are sanctioned.
- `python -m py_compile` every changed Python file + run the matching test; `npm.cmd run build` if frontend changed. If anything fails → revert.
- Health problems in the daily report are fixed **before** any new feature.
- Backend changes take effect via the watchdog `restart.requested` flag (only when no render is running).

## Done
- **2026-10-14** — **Subscriber-growth agent (24×7 delivery guarantee).** A new always-on agent (`app/growth/`) that closes the real gap the scheduler leaves: `next_run` advances as soon as a job is *queued*, so a render that failed (or an upload run that errored) is never retried that day. Every minute the voice-agent loop calls `growth_agent.tick()`, which (1) re-queues a scheduled show that has no completed video for the day, (2) re-runs a social upload for any platform still missing a finished video, and (3) rotates the daily hook / CTA / hashtag variant used by `theme_for()` so appeals vary day to day. ToS-safe by design — no bots, no auto-likes/follows/comments, no paid engagement. Gaps are tracked **per platform** (uploader logs are keyed by job id; note YouTube's log is `uploaded.log`, not `*_uploaded.log`) and re-running is safe because each uploader skips anything already in its own log. State/limits in `storage/growth/` (`config.json`, `state.json`, `events.jsonl`, `reports/<date>.json`); API at `/growth/status|report|tick|config`; grace 45 min, ≤4 render recoveries/day, ≤3 upload retries/day, ≥5 min between actions. Verified live: it found today's true gaps — Facebook missing `history`+`indian-law`, Instagram missing `indian-law`, YouTube missing `history`+`indian-law` — re-ran Facebook (**Posted 2/2 OK**) and Instagram automatically, and correctly left renders alone (`missed_renders: []`). Guard test `growth_test.py` **45/45**.
- **2026-10-14** — **Facebook + Instagram kept logging out — root cause fixed.** The uploaders launched a **brand-new throwaway Chrome** every run and injected a cookie snapshot from `storage_state.json` that was **never written back**. FB/IG rotate the auth cookie (`xs` / `sessionid`) during each session and bind it to the browser fingerprint (Instagram answers a mismatched agent with `{"message":"useragent mismatch"}`), so the next run presented an already-invalidated snapshot from a “new device” and the account looked logged out — which is why a fresh manual login worked once and then died. The uploaders and the login capture now share **one persistent Chrome profile** (`C:\Users\sys\AppData\Local\CreatorSocial\chrome-profile`, the same trick the YouTube uploader already uses) via `projects/*/social_session.py`: it is seeded once from the existing `storage_state.json` and the live rotated cookies are mirrored back on exit. `save_social_login.py` was rewritten to log in *inside that same profile* (so a manual login finally persists) and to stop overwriting one site's good cookies when only the other has logged in. Verified without posting: two consecutive launches of the persistent profile were each still logged in on Facebook **and** Instagram, and the live recovery run then posted through it successfully.
- **2026-10-14** — **Animated Like · Share · Subscribe end-card on every video.** A new frame-accurate Chromium renderer (`render_outro_frames.cjs`) draws a themed end-card — show badge, `Like · Share · Subscribe` heading, three buttons that pop in one after another, a red **Subscribe** button whose bell swings and pulses, a floating tagline and an optional channel name — and `render_scenes` now appends it as **one extra final scene** reusing the existing crossfade/audio-bed/music machinery (`raw`/`starts`/`total`/`scene_count` are extended by one). The old ASS `Cta` event was removed because the designed end-card replaces it. Config: `OUTRO_SECONDS` (3.4) and `CHANNEL_NAME` (empty = generic tagline) in settings. Verified end-to-end on a real 5-scene job: 6 sequences rendered (5 content + `seq-5` with exactly 82 outro frames = 3.4 s × 24 fps), timeline arithmetic matched to the frame (`127.33 s` MP4, outro starts 123.93 s), the red subscribe button is present at 126.3 s and absent at 122.8 s (last content scene), ASS styles are now `['Sub','Hook']`, the last caption ends 121.50 s so captions never overlap the end-card, and the progress bar finishes fully lit. A short clip was left at `storage/previews/outro_demo_clip.mp4`.
- **2026-10-14** — **Viewer-retention pack + a real caption-timing bug fixed.** (1) **Bug (high impact):** libass treats the seconds *fraction* in an ASS timestamp as a whole number of **centiseconds**, so the old `_ass_time` emitting 3-digit milliseconds (`…00.100`) actually rendered at **1.0 s**. Every burned caption in every video so far appeared ~3–9 s late, and most fell outside the clip entirely (proved on a real posted job: the first caption was absent at its true 0.4 s and present at 1.3 s). `_ass_time` now emits canonical `H:MM:SS.cc` — captions are back on the narration. (2) **Progress bar** burned into the top edge of every frame (a strong retention cue). (3) **Hook + end CTA** via ASS: the show name in an accent pill for the first ~2.8 s, and `தினமும் புது வீடியோ · Follow + Share` over the last ~3 s. (4) **Highlighted captions**: numbers and short exclamations are drawn in the show's accent colour. (5) **Per-show identity** (`theme.py`): one accent colour per kind now drives the illustration, the Chromium scene card (redesigned — rounded glass card, badge + `n / N` pill, accent rule, per-line accent bars, faint number watermark), the captions and the bar. Verified end-to-end on a real render (25.96 s MP4): progress bar 50 → 542 → 1042 px, hook box, CTA box, caption highlight and correct caption windows all confirmed by pixel checks; also fixed a pre-existing NaN warning in the transition swell.

- **2026-10-14** — **Why the owner's existing Chrome login can't be reused (finding).** Chrome 136+ **ignores `--remote-debugging-port` when `--user-data-dir` is the default profile path**, and Chrome 127+ **App-Bound Encryption** (`v20` cookie values) ties decryption to the *original* profile path. Verified end-to-end: a full-profile copy at a non-default path opens CDP but decrypts to **0 cookies**; the default path refuses CDP. Net: the FB/IG login in the owner's everyday Chrome **cannot** be lifted programmatically — a one-time login inside the uploader's own browser (`save_social_login.py`, desktop shortcut *Connect-Facebook-Instagram*) is required. Do not re-attempt cookie extraction.
- **2026-10-14** — **Watchdog restart outage (incident fix).** `watchdog.ps1` killed the backend for a self-upgrade / stale-voice self-heal but never started it again — it relied on the *next* 10-minute tick, so each self-heal took the whole site offline for up to 10 minutes (observed: killed 09:15, backend down until 09:16 manual start; English render at 09:20 nearly missed). Added `Start-Backend` / `Restart-Backend` helpers: kill → wait for the port to free → start immediately → log. Both the self-upgrade and voice-stale paths now restart atomically.
- **2026-10-14** — **Social-login hardening + restart safety.** `save_social_login.py` waited only 3 minutes per site and — worse — wrote `storage_state.json` even when no login was detected, so a failed attempt could clobber a good session. It now waits 15 minutes per site (`SITE_TIMEOUT`) and only saves when at least one site reported a login. Added a desktop shortcut **Connect-Facebook-Instagram.cmd** so the one-time connect can be done any time. `ops_restart.py` now also defers an autonomous restart while an **upload** run is active (it previously only checked video renders), so a self-upgrade restart can no longer kill a Playwright upload.
- **2026-10-14** — **Voice resilience (incident fix).** Two morning renders (08:00 history, 08:05 indian-law) failed with `WSServerHandshakeError: 403` — Microsoft was rejecting edge-tts 7.2.8's `Sec-MS-GEC` token. The daily report's `ok` now includes `voice_ok`.
